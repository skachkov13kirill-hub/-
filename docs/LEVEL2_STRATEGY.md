## Порядок реализации (8 задач)

### Задача 1: Умный дедубликатор
**Проблема:** id транзакций генерируется через `Math.random()`. Если загрузить тот же PDF дважды — создадутся дубликаты, потому что проверка `existingIds.has(t.id)` не сработает (id будут новые).

**Решение:** Заменить random id на детерминированный хеш из `дата + сумма + описание + банк`. Тогда один и тот же PDF всегда даёт одинаковые id.

**Как именно:**
```
id = bank_prefix + "_" + date + "_" + amount + "_" + hash(description.substring(0,30))
```
Хеш — простой: `str.split('').reduce((h, c) => (h * 31 + c.charCodeAt(0)) & 0x7FFFFFFF, 0).toString(36)`

**Возможные ошибки:**
- Две разных операции в один день с одинаковой суммой и похожим описанием → коллизия. Решение: добавить в хеш ещё и время (time), если оно есть.
- Старые транзакции (с random id) останутся в localStorage → нужна миграция: при загрузке STATE пересчитать id для всех существующих транзакций, удалить дубли.

**Порядок действий:**
1. Написать функцию `generateTxId(bank, date, time, amount, description)`
2. Заменить генерацию id в parseSber() и parseTinkoff()
3. Добавить миграцию в loadState(): пересчитать id для старых записей
4. Проверить, что повторная загрузка того же PDF не создаёт дубли

### Задача 2: Экспорт/Импорт данных (бэкап в JSON)
**Проблема:** localStorage — единственное хранилище. Очистка кеша = потеря всех данных. Нет переноса между устройствами.

**Решение:** Две кнопки в настройках: «Сохранить копию» и «Загрузить из копии».

**Как именно:**
- Экспорт: `JSON.stringify(STATE)` → Blob → скачать как `finance_backup_ДАТА.json`
- Импорт: FileReader → JSON.parse → валидация структуры → мержить с текущими данными или заменить

**Возможные ошибки:**
- Пользователь загружает битый JSON → нужна try/catch с понятным toast-сообщением
- Пользователь загружает старую версию бэкапа без новых полей (comment, manual и т.д.) → нужна проверка версии и миграция
- Мержить или заменять? → Спросить пользователя через confirm: «Заменить все данные или добавить к существующим?»

**Порядок действий:**
1. Добавить в STATE поле `version: 2` (текущая = 1, без версии)
2. Написать `exportBackup()` — скачивает JSON
3. Написать `importBackup()` — читает файл, валидирует, мержит/заменяет
4. Добавить кнопки в секцию «Данные» настроек
5. Добавить миграцию версий в loadState()

### Задача 3: Миграция на IndexedDB (критически важно)
**Проблема:** localStorage ограничен 5 МБ, синхронный (блокирует UI), не работает в Service Worker. При 1000+ транзакциях JSON.stringify начинает тормозить.

**Что я узнал из исследования:**
- IndexedDB поддерживает до 50%+ диска (сотни МБ)
- Библиотека `idb-keyval` (295 байт!) даёт API как у localStorage, но на IndexedDB
- На iOS Safari данные удаляются через 7 дней если приложение не добавлено на домашний экран
- Можно запросить persistent storage через `navigator.storage.persist()`

**РЕШЕНИЕ — УПРОЩЁННЫЙ ПОДХОД:**
Вместо полной миграции на IndexedDB (сложно, много переделывать) — использовать гибридный подход:
1. Оставить STATE в памяти как сейчас
2. Сохранять в IndexedDB через idb-keyval (один вызов `set('state', STATE)`)
3. При загрузке — читать из IndexedDB, фоллбэк на localStorage
4. Запросить persistent storage

Это минимальные изменения: заменить `localStorage.setItem/getItem` на `idbKeyval.set/get`, всё остальное остаётся.

**Но! Есть нюанс:** idb-keyval — это npm-пакет, а у нас один HTML-файл без сборки. Решение: встроить минифицированный код idb-keyval прямо в HTML (он всего 295 байт) или написать свой простой wrapper (10 строк кода).

**Возможные ошибки:**
- IndexedDB асинхронный → saveState() станет async → все вызовы saveState() нужно проверить
- Первый запуск: IndexedDB пуста, localStorage может содержать данные → нужна автомиграция
- Safari Private Browsing: IndexedDB может быть недоступна → фоллбэк на localStorage

**РЕШЕНИЕ: ОТЛОЖИТЬ НА ПОТОМ.**
На текущем этапе localStorage достаточно (5 МБ = ~15,000 транзакций). Миграция на IndexedDB нужна когда:
- Появятся жалобы на переполнение
- Нужен Service Worker для офлайн-кэша
- Начнём работать с изображениями/файлами

Сейчас: добавить мониторинг использования localStorage (показать в настройках сколько занято).

**Порядок действий:**
1. Написать функцию `getStorageUsage()` — возвращает размер данных в localStorage
2. Показать в настройках: «Использовано: X.X МБ из ~5 МБ»
3. Предупреждение если > 4 МБ: «Данных много, рекомендуем сделать бэкап»
4. TODO на будущее: миграция на IndexedDB когда понадобится

### Задача 4: Бюджеты по категориям
**Проблема:** Нет инструмента для контроля трат. Пользователь видит что потратил, но не может задать лимит.

**Решение:** В настройках — список категорий с полями для лимитов. На дашборде — прогресс-бары у категорий. В советнике — предупреждения при приближении к лимиту.

**Как именно:**
- STATE.budgets = { 'Еда вне дома': 15000, 'Развлечения': 5000, ... }
- На дашборде рядом с суммой категории показать прогресс-бар к бюджету
- Цвет: зелёный < 70%, жёлтый 70-90%, красный > 90%
- В советнике: если категория > 80% бюджета → предупреждение

**Возможные ошибки:**
- Пользователь не задал бюджет → не показывать прогресс-бар (только для заданных)
- Бюджет = 0 или отрицательный → валидация на вводе
- При смене месяца бюджеты должны оставаться → хранить в settings, не в данных месяца

**Порядок действий:**
1. Добавить STATE.budgets = {} в defaultState()
2. Добавить карточку «Бюджеты» в настройках с редактируемыми полями
3. В renderCategories() добавить прогресс-бар бюджета если задан
4. В renderAdvisor() добавить проверку бюджетов
5. В openExpenseDetail() показать статус бюджета

### Задача 5: Графики трендов (месяц к месяцу)
**Проблема:** Нет визуализации динамики. Пользователь видит один месяц, но не тренды.

**Решение:** Новый экран «Тренды» (или секция на дашборде) с линейными графиками.

**Что я узнал:** Chart.js уже подключён. Нужны:
1. Линейный график: расходы по месяцам (линия)
2. Столбчатый график: доходы vs расходы по месяцам (два столбца)
3. Линейный по категориям: выбрать категорию → увидеть динамику

**Как именно:**
- Экран «Календарь» (который сейчас слабо используется) → переименовать в «Тренды»
- Оставить регулярные платежи, но добавить графики сверху
- Данные: getAvailableMonths() → для каждого месяца посчитать income/expense/по категориям

**Возможные ошибки:**
- Мало данных (1-2 месяца) → графики бессмысленны → показать текст «Загрузите выписки за 3+ месяцев»
- Слишком много месяцев → график мелкий → ограничить последними 12
- Canvas переиспользование → нужно destroy() старый чарт перед созданием нового (как с donutChart)
- Месяцы могут быть с пропусками → ось X должна быть равномерной

**Порядок действий:**
1. Заменить экран «Календарь» на «Тренды» (переименовать nav-item)
2. HTML: добавить canvas элементы для 2-3 графиков
3. Написать renderTrends() — собирает данные по всем месяцам
4. График 1: линейный расходы по месяцам
5. График 2: столбчатый доходы vs расходы
6. Оставить раздел с регулярными платежами ниже
7. Добавить селектор категории для детального графика

### Задача 6: Умные цели
**Проблема:** Нет мотивации экономить. Нет конкретной цели.

**Решение:** Секция «Цели» в настройках. Карточка на дашборде с прогрессом.

**Как именно:**
- STATE.goals = [{ name: 'Отпуск', target: 100000, deadline: '2025-12', saved: 0 }]
- На дашборде: карточка с прогресс-баром и расчётом «нужно откладывать X ₽/мес»
- Автоподсчёт: разница income - expenses за прошлые месяцы → «вы в среднем откладываете Y ₽/мес»

**Возможные ошибки:**
- saved вручную? Или автоматически? → Автоматически = (income - expenses) за каждый месяц. Но это не точно (деньги могли уйти на другую цель). Лучше: показать «при текущем темпе» и дать кнопку «отложил вручную».
- Несколько целей → показывать все, сортировать по дедлайну
- Цель без дедлайна → показать только прогресс-бар без расчёта «сколько в месяц»

**Порядок действий:**
1. Добавить STATE.goals = [] в defaultState()
2. Добавить карточку «Цели» в настройках с формой добавления
3. На дашборде: карточка первой цели с прогрессом
4. Расчёт: средняя экономия за доступные месяцы → прогноз достижения цели
5. В советнике: подсказки привязанные к целям

### Задача 7: Улучшение парсеров + Альфа-Банк
**Проблема:** Только 2 банка. Альфа-Банк — третий по популярности.

**Что я узнал:**
- PDF-выписка Альфа-Банка скачивается из интернет-банка ibank.alfabank.ru
- Формат PDF не документирован, нужен реальный образец для написания парсера
- У Альфа-Банка есть также CSV и 1С экспорт → можно добавить поддержку CSV
- ВТБ тоже даёт PDF-выписки, но формат неизвестен

**РЕШЕНИЕ: ПРАГМАТИЧНЫЙ ПОДХОД:**
1. Добавить поддержку CSV-импорта (универсально — работает для любого банка)
2. Улучшить существующие парсеры Сбер и Тинькофф
3. Альфа-Банк PDF — только если будет образец

**Как добавить CSV-импорт:**
- Принимать .csv файлы наравне с .pdf
- Формат: Дата, Описание, Сумма, Категория (опционально)
- Автоматическое определение разделителя (запятая/точка с запятой/табуляция)
- Автоопределение колонок по заголовкам

**Улучшение существующих парсеров:**
- Добавить подсчёт: «Разобрано X из Y строк» для отладки
- Логирование нераспознанных строк в консоль
- Валидация: если найдено < 5 транзакций в PDF → предупреждение «Возможно, формат изменился»

**Возможные ошибки:**
- CSV с разной кодировкой (UTF-8, Windows-1251) → определять по BOM или пробовать обе
- Дата в разных форматах (ДД.ММ.ГГГГ, ГГГГ-ММ-ДД, ДД/ММ/ГГГГ) → регулярки для всех вариантов
- Сумма с минусом / плюсом / в скобках / с пробелами → нормализация
- CSV из Excel с кавычками и запятыми внутри значений → использовать правильный парсер CSV

**Порядок действий:**
1. Расширить input accept на ".pdf,.csv"
2. Написать parseCSV() с автоопределением формата
3. В handleFiles() определять тип файла и вызывать нужный парсер
4. Добавить в parseSber/parseTinkoff: счётчик разобранных строк, логирование
5. Показать результат парсинга: «X операций, Y нераспознано»

### Задача 8: Шаринг отчёта (генерация картинки)
**Проблема:** Нельзя поделиться результатами. Нельзя показать другу «смотри как я потратил».

**Что я узнал:**
- html2canvas → Canvas → toBlob() → navigator.share({ files }) — работает в PWA
- Web Share API поддерживается в Chrome Android, Safari iOS — основные мобильные браузеры
- На десктопе Web Share API ограничен → фоллбэк на скачивание PNG

**Как именно:**
1. Кнопка «Поделиться сводкой» на дашборде
2. Создать скрытый div с красивой карточкой (доходы/расходы/экономия/топ-3 категории)
3. html2canvas → рендерим в Canvas
4. Canvas.toBlob() → создать File
5. navigator.share({ files }) — нативный шаринг
6. Фоллбэк: скачать как PNG

**Проблемы и решения:**
- html2canvas — это CDN-библиотека (~40 КБ) → подключить через CDN только при нажатии на кнопку (lazy load)
- Тёмная тема → генерировать картинку всегда в светлой теме для читаемости
- Разный размер экранов → фиксированный размер карточки (600x800px)
- navigator.share может не поддерживаться → проверка `navigator.canShare`

**Порядок действий:**
1. Добавить кнопку «📤 Поделиться» на дашборде
2. Создать шаблон карточки (скрытый div) с итогами месяца
3. Lazy-load html2canvas из CDN
4. Генерация Canvas → Blob → File
5. navigator.share с фоллбэком на download

## Общий порядок реализации

```
1. Дедубликатор      (1 час)   — фундамент, без него всё остальное ненадёжно

```

## Что НЕ делаем в Level 2 (и почему)

- **IndexedDB миграция** — localStorage хватит на 15,000+ транзакций, усложнение не оправдано
- **Service Worker офлайн** — приложение и так работает офлайн (всё в одном HTML)
- **Парсер Альфа/ВТБ PDF** — нет образцов, вместо этого универсальный CSV-импорт
- **Серверный бэкенд** — это Level 3, для коммерции
- **AI-советник** — требует API-ключ и расходы, это платная фича
- **Push-уведомления** — требуют Service Worker и разрешение пользователя, усложняют

## Риски и как их избежать

| Риск | Вероятность | Решение |
|------|-------------|---------|
| Сломать существующие данные | Высокая | Бэкап первым делом, миграция версий |
| localStorage переполнение | Средняя | Мониторинг + предупреждение + бэкап |
| html2canvas не рендерит правильно | Средняя | Фиксированный layout, тестирование |
| Chart.js конфликт при нескольких графиках | Низкая | Правильный destroy() перед пересозданием |
| CSV с кривой кодировкой | Высокая | Пробовать UTF-8, затем Windows-1251 |
| Web Share API не поддерживается | Средняя | Фоллбэк на скачивание PNG |
