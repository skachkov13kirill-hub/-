## ЭТАП 1: КРИТИЧЕСКИЕ БАГИ (без этого всё остальное бессмысленно)

### 1.1 BUG-2: txHash — дедупликация [ЧАСТИЧНО СДЕЛАНО]
**Файл:** `js/app.js:8-17`
**Проблема:** Одинаковые транзакции с разным регистром создают разные хеши → дубли
**Фикс:** Нормализовать desc в txHash: `.toUpperCase().replace(/\s+/g, ' ').trim()`
**Статус:** Код изменён (строка 9), но НЕ протестировано. Нужно проверить что существующие данные не потеряются (старые хеши vs новые)
**Риск:** После изменения хеша старые транзакции будут иметь другие ID → при повторной загрузке PDF они добавятся заново. Нужна миграция или ре-хеширование при loadState()

### 1.2 BUG-4: Внутренние переводы считаются расходами [КРИТИЧЕСКИЙ]
**Файл:** `js/app.js:483-534` (categorizeTransaction) + `js/app.js:263-481` (MERCHANT_RULES)
**Проблема:** KOPILKA, KARTA-VKLAD, SBOL перевод, Пополнение вклада — это переводы себе, но type='expense'. Из-за этого расходы показывают 4.27M₽ вместо реальных ~500-800K₽
**Что делать:**
1. В categorizeTransaction() — добавить определение type='transfer' для:
   - KOPILKA / КОПИЛКА → type: 'transfer', category: 'Перевод себе'
   - KARTA-VKLAD / КАРТА-ВКЛАД → type: 'transfer', category: 'Перевод себе'
   - SBOL PEREVOD / СБОЛ ПЕРЕВОД → type: 'transfer', category: 'Перевод себе'
   - Пополнение вклада → type: 'transfer', category: 'Перевод себе'
   - MAPP_SBERBANK → type: 'transfer', category: 'Перевод себе'
   - Перевод между счетами → type: 'transfer', category: 'Перевод себе'
2. Проблема: categorizeTransaction() возвращает только category, не type. Нужно либо:
   - (а) Вернуть объект {category, type} вместо строки → рефакторинг всех вызовов
   - (б) Сделать отдельную функцию classifyTransferType(desc) → вызывать в парсерах после categorize
   - Рекомендация: вариант (б) — меньше ломает существующий код

### 1.4 BUG-1: Доходы = 0₽ на дашборде [КРИТИЧЕСКИЙ]
**Файл:** `js/app.js:1198` (renderDashboard) + `js/app.js:1145-1163` (applyDashFilter)
**Проблема:** dashToggles по умолчанию = `{ expenses: true, transfers: false, self: false, income: false }`. Income = false! Поэтому income всегда 0.
**Причина:** Строка 1198: `const income = data.filter(t => t.type === 'income')` — но data уже отфильтрована через applyDashFilter(), который отсекает income (dashToggles.income = false)
**Фикс:** Доходы всегда считать из allData (не отфильтрованных), а не из data. Строка 1198:
```javascript
// Было:
const income = data.filter(t => t.type === 'income').reduce(...)
// Надо:
const income = allData.filter(t => t.type === 'income').reduce(...)
```
**Также:** forecast, health score, comparison — тоже нужен allData для income

### 1.5 BUG-5: Фильтры дашборда не переключают вид [СРЕДНИЙ]
**Файл:** `js/app.js:1136-1143` (updateDashToggleUI)
**Проблема:** Кнопки «Расходы / Переводы / Себе / Доходы» визуально переключаются, но данные те же
**Причина:** BUG-4 — если все транзакции имеют type='expense', то фильтр не может разделить их на группы. Фикс BUG-4 автоматически починит BUG-5
**Дополнительно:** Проверить что HTML data-dtoggle атрибуты совпадают с ключами dashToggles

### 1.6 BUG-7: Категории показывают 0% [МАЛЫЙ]
**Файл:** `js/app.js:1336-1373` (renderCategories)
**Проблема:** `pct = totalExpense > 0 ? Math.round(amount / totalExpense * 100) : 0`
**Причина:** totalExpense передаётся как параметр expenses из renderDashboard. Если expenses = 0 (из-за фильтра) → все 0%
**Фикс:** Зависит от фикса BUG-1 и BUG-4. Если expenses правильно считаются, проценты тоже будут правильными

### 1.7 BUG-6: Абсурдные числа в прогнозе [СРЕДНИЙ]
**Файл:** `js/app.js:1236-1278` (renderForecast)
**Проблема:** «Остаток: 4,270,269₽, Можно в день: 0₽» — потому что income=0 и expenses=4.27M (всё = расходы)
**Фикс:** Автоматически исправится после BUG-4 (корректные type) и BUG-1 (корректный income)

## ЭТАП 2: UX-ФИКСЫ (чистка для пользовательского опыта)

### 2.1 UX-1: Чистка названий транзакций
**Проблема:** Пользователь видит «MAPP_SBERBANK_ONL@IN_PAY RUS MOSKVA 643 48037769» вместо «Пятёрочка»
**Что делать:** Создать функцию `cleanDescription(desc)`:
```javascript
function cleanDescription(desc) {
  let d = desc;
  d = d.replace(/^MAPP_/i, '');
  d = d.replace(/_ONL@IN_PAY/i, '');
  d = d.replace(/\s+RUS\s+\w+/i, '');  // убрать RUS MOSKVA
  d = d.replace(/\s+\d{3}\s+\d{8,}/g, ''); // убрать 643 48037769
  d = d.replace(/\*{4}\d{4}/g, '');  // убрать ****1234
  d = d.replace(/\s+/g, ' ').trim();
  return d;
}
```
**Где применять:** В рендере транзакций (для отображения), НЕ в данных (чтобы не сломать правила)

1. **Данные первичны** — без фикса багов тренды и геймификация считают мусор
2. **Vanilla JS** — никаких фреймворков, один файл app.js
3. **Offline-first** — всё работает без интернета
4. **Приватность** — данные не покидают устройство
5. **Не ломать** — каждый фикс тестировать на существующих данных
6. **UX Monefy** — простота ввода, мгновенная обратная связь
7. **Анти-CoinKeeper** — никакой агрессивной монетизации, честные лимиты
8. **Apple-quality** — каждое действие можно отменить, каждый экран понятен
