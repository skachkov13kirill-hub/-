# Финансовый Помощник — Стратегия монетизации и юнит-экономика

---

## 1. Честный взгляд: что у нас есть и чего нет

**Что есть:** PWA-приложение без серверной части. Всё работает в браузере, данные на устройстве пользователя. Парсинг PDF-выписок Сбера и Тинькофф, аналитика, советник.

**Что это даёт:**
- Нулевые серверные расходы (пока нет бэкенда)
- Нулевые проблемы с 152-ФЗ (данные не покидают устройство)
- Нулевой CAC через сарафанное радио (если продукт хороший)
- Но: нет банковской интеграции, нет синхронизации между устройствами, нет возможности продавать через App Store

## 2. Модели монетизации — что выбрать

### Вариант A: Freemium + Подписка (РЕКОМЕНДУЮ)

**Бесплатно (навсегда):**
- Загрузка PDF, парсинг, категоризация
- Дашборд с основной аналитикой
- До 3 месяцев данных
- 1 банк (Сбер или Тинькофф)
- Базовый советник

**PRO подписка (199 ₽/мес или 1 490 ₽/год):**
- Безлимитная история (все месяцы)
- Все банки + CSV-импорт
- Бюджеты по категориям
- Графики трендов
- Умные цели
- Семейный режим (2+ человек)
- Экспорт в Excel/CSV
- Шаринг отчётов
- Split-транзакции
- Приоритетная поддержка

**Почему 199 ₽/мес:**
- Дзен-мани берёт 99 ₽/мес — мы дороже, потому что не требуем ручного ввода
- CoinKeeper Platinum — 149 ₽/мес
- YNAB — $14.99/мес (≈1 400 ₽) — на порядок дороже
- 199 ₽ — это цена кофе, психологически «ничего не стоит»
- 1 490 ₽/год — скидка 38%, мотивирует подписаться на год

### Вариант B: Разовая покупка (НЕ рекомендую)

- 990 ₽ разово — кажется проще, но:
- Нет recurring revenue
- Нет мотивации развивать продукт
- Пользователь заплатил и забыл
- Monefy Pro = 279 ₽ — конкурировать с ценой нереально

### Вариант C: Гибридная модель (НА БУДУЩЕЕ, Level 3+)

Как Rocket Money:
- Подписка + комиссия от экономии
- «Мы нашли 3 подписки, которые вы не используете. Отменить? Экономия: 1 200 ₽/мес»
- Комиссия: 30% от первого года экономии
- Требует банковскую интеграцию и юридическую базу

## 4. Проблема PDF vs банковская интеграция

### PDF-выписки (то что есть сейчас)

**Плюсы:**
- Нулевые затраты на интеграцию
- Не нужны API-ключи, договоры с банками
- 100% приватность (данные на устройстве)
- Работает без интернета
- Нет зависимости от банка (банк поменял API = не наша проблема)

**Минусы:**
- Нужно скачивать PDF вручную каждый месяц
- Это ДЕЙСТВИЕ, которое убьёт конверсию у 50%+ пользователей
- Не real-time (данные запаздывают)
- Разный формат выписок у разных банков — вечная поддержка парсеров

### Банковская интеграция (как Дзен-мани)

**Способы интеграции в России (2026):**

1. **Через SMS/push-уведомления** — приложение читает банковские SMS
   - Плюс: просто, не нужен API
   - Минус: требует разрешение на чтение SMS (Android), неточно, не работает на iOS

2. **Через email-уведомления** — парсинг писем от банка
   - Плюс: работает на всех платформах
   - Минус: нужен доступ к почте, задержка

3. **Open Banking API (ЦБ РФ)** — стандарт в разработке
   - Статус: пилот 5 крупнейших банков (Сбер, Тинькофф, Альфа, Газпромбанк, ВТБ)
   - Обязательный переход: планируется на октябрь 2026
   - Плюс: официальный, надёжный
   - Минус: пока не работает для третьих сторон, нужна сертификация

4. **Через агрегаторы (Salt Edge)** — работают в 44 странах
   - Стоимость: от €500/мес за базовый доступ
   - Покрытие в РФ: ограничено
   - Плюс: единый API для всех банков
   - Минус: дорого, зависимость от агрегатора

5. **Scraping банковских личных кабинетов** — как делали раньше
   - Минус: незаконно с 2023, банки блокируют

### Рекомендация: ГИБРИДНЫЙ ПОДХОД

**Фаза 1 (сейчас):** PDF — бесплатно и работает
**Фаза 2 (через 6 мес):** Добавить парсинг email-уведомлений от банков (не нужен доступ к банку, только к почте)
**Фаза 3 (2026-2027):** Open Banking API — когда ЦБ сделает его обязательным

Между фазой 1 и 2 — добавить «умный импорт»:
- Пользователь пересылает банковские уведомления на специальный email
- Или копирует текст push-уведомления → приложение парсит
- Или фотографирует чек → OCR

**Снижение трения PDF:**
- Инструкция «Как скачать выписку» для каждого банка (со скриншотами)
- Deeplink в банковское приложение (если возможно)
- Напоминание раз в месяц: «Загрузите свежую выписку»
- Геймификация: «Серия: 3 месяца подряд! Не прерывайте!»

### Архитектура «Premium-ready»

Добавить в код систему feature flags:

```javascript
// В STATE.settings:
plan: 'free', // 'free' | 'pro' | 'trial'
trialStartDate: null,
trialDays: 14,

// Проверка доступа:
function isPro() {
  if (STATE.settings.plan === 'pro') return true;
  if (STATE.settings.plan === 'trial') {
    const start = new Date(STATE.settings.trialStartDate);
    const now = new Date();
    const days = (now - start) / (1000 * 60 * 60 * 24);
    return days <= STATE.settings.trialDays;
  }
  return false;
}

function requirePro(featureName) {
  if (isPro()) return true;
  showProModal(featureName);
  return false;
}
```

- Или: QR-код для оплаты → проверка по email

## 7. Риски и что будет если «выстрелит»

### Если начнёт продаваться — что ляжет на плечи

**1. Поддержка пользователей (с 100+ платящих)**
- Telegram-канал + чат поддержки
- FAQ на сайте
- 2-3 часа в неделю на ответы
- Самый частый вопрос: «Как скачать выписку из банка X»

**2. Парсеры ломаются (с 1 000+ пользователей)**
- Банки обновляют формат PDF → парсер перестаёт работать
- Нужно: мониторинг ошибок + быстрый фикс
- Решение: пользователи присылают «битые» PDF → ты чинишь парсер
- Это самый трудоёмкий операционный процесс!

**3. Новые банки (с 5 000+ пользователей)**
- «Добавьте Альфа-Банк!» «Добавьте ВТБ!» «Добавьте Райффайзен!»
- Каждый банк = 4-8 часов работы + тестирование
- Решение: CSV-импорт как универсальный fallback

**4. Юридические риски**
- 152-ФЗ: если данные утекут — штраф до 5 млн ₽ (с сентября 2025)
- Но: у нас данные НА УСТРОЙСТВЕ, мы не храним их на сервере
- Если добавим сервер — нужна серьёзная инфраструктура безопасности
- Совет: как можно дольше оставаться в модели «данные на устройстве»

**5. App Store / Google Play (с 10 000+ пользователей)**
- PWA не требует App Store — огромное преимущество
- Но пользователи хотят «нормальное приложение»
- Google Play: комиссия 15-30% от подписок
- RuStore: комиссия 0% (пока)
- Решение: PWA + RuStore первым делом

- Не тратить на рекламу до product-market fit (первые 200 пользователей должны быть органическими)

## 11. Самый главный вопрос: стоит ли это делать?

### Аргументы ЗА

- Рынок растёт на 25% в год
- Mint закрылся — освободилась ниша
- В России нет хорошего бесплатного решения
- CoinKeeper и Дзен-мани теряют пользователей (по отзывам)
- Нулевые начальные затраты (PWA, нет сервера)
- LTV:CAC = 20:1 (отличная экономика)
- Встроенная аналитика банков показывает только ОДИН банк

### Аргументы ПРОТИВ

- Ручная загрузка PDF — барьер для 50%+ пользователей
- Open Banking API в РФ — пока не готов
- Один разработчик = медленная итерация
- Парсеры будут ломаться при обновлении банков
- 152-ФЗ ужесточается — риски при масштабировании

### Вердикт

**Стоит запускать.** Нулевые затраты на старте, понятная unit-экономика, растущий рынок. Главный риск — трение с PDF, но его можно снизить (инструкции, напоминания, email-парсинг). К 2027 году Open Banking API в России станет обязательным — и тогда главный барьер исчезнет. Задача: дожить до этого момента с лояльной базой пользователей.

**Целевой результат первого года:** 30 000 пользователей, 1 150 платящих, MRR 228 850 ₽, прибыль ~440 000 ₽. Не деньги, на которые можно жить, но proof-of-concept для инвестиций или роста.
